Вторая рабочая контрольная точка

Собери строго это состояние:

палитра уже существует

можно перетащить базовый объект на пустую форму

объект визуально появляется на canvas

объект можно выбрать

его свойства показываются слева

можно изменить text

можно удалить объект

можно двигать объект

можно менять размер объекта

после каждого завершенного действия обновляется JSON snapshot


На этой точке не подключай специальные контейнеры.
Закрой полностью только базовый сценарий для обычных leaf-объектов.


---

1. Цель второй контрольной точки

Доведи систему до первого реально полезного конструктора.

Пользователь должен уже мочь:

1. создать пустую форму


2. перетащить на нее кнопку


3. выбрать кнопку


4. поменять надпись


5. передвинуть кнопку


6. изменить размер


7. удалить кнопку



После этого можно переходить к контейнерам и сложным типам.


---

2. Типы, которые подключай на этой точке

Не подключай сразу все.
Начни только с этого набора:

QLabel

QPushButton

QLineEdit


После их стабилизации добавь:

QCheckBox

QRadioButton

QComboBox


Но сначала добейся полной стабильности на первых трех типах.

3. Подключи создание обычных сущностей в FormDocument

Расширь document/form_document.py.

Добавь или доведи до рабочего состояния:

Методы

create_entity(type_name, parent_id, geometry=None, properties=None, name=None) -> EntityModel

delete_entity(entity_id) -> None

delete_subtree(entity_id) -> None

rename_entity(entity_id, new_name) -> None

update_property(entity_id, property_name, value) -> None

update_geometry(entity_id, x, y, width, height) -> None

move_entity(entity_id, x, y) -> None

resize_entity(entity_id, width, height) -> None



---

Поведение create_entity(...)

Реализуй строго так:

1. проверить, что type_name существует в registry


2. проверить, что parent_id существует или равен form_root


3. получить определение типа из registry


4. сгенерировать id


5. сгенерировать name, если не передано


6. взять дефолтные properties


7. взять дефолтный default_size


8. если geometry не передано:

x = 0

y = 0

width/height из реестра



9. если geometry передано:

нормализовать через utils.geometry



10. вычислить order среди детей родителя


11. создать EntityModel


12. записать в entities_by_id


13. пометить документ dirty


14. вернуть созданную сущность




---

Поведение delete_entity(...)

Для второй точки разреши удаление только обычных leaf-объектов.

Логика:

1. проверить существование объекта


2. удалить его из entities_by_id


3. пометить документ dirty



Если у объекта вдруг есть дети:

вызови delete_subtree(...)



---

Поведение delete_subtree(...)

1. получить всех потомков


2. удалить потомков снизу вверх


3. удалить корневую сущность


4. пометить документ dirty




---

6. Создай LeafItemView

В canvas/views/leaf_item_view.py создай LeafItemView, наследник BaseFormItemView.


---

Добавь

выбор объекта по клику

drag move

базовое отображение выделения



---

Методы

mousePressEvent(event)

mouseMoveEvent(event)

mouseReleaseEvent(event)

paintEvent(event)



---

Поведение выбора

При клике:

1. передать entity_id в canvas


2. canvas передает выбор в контроллер


3. контроллер обновляет selected state


4. canvas обновляет выделение всех item view




---

Поведение drag move

На второй точке реализуй только перемещение внутри текущего родителя.

Во время drag:

двигай только визуальную оболочку


После mouse release:

вычисли новые x/y

передай в canvas

canvas передает в контроллер

контроллер обновляет документ

serializer обновляет snapshot



---

Поведение выделения

В paintEvent рисуй простую рамку, если is_selected = true.

Пока достаточно:

1 прямоугольная рамка

без красивых handles

8. Расширь CanvasEditor

В canvas/canvas_editor.py сделай рабочий визуальный слой.


---

---

Методы

clear_selection()

handle_item_clicked(entity_id)

handle_item_move_finished(entity_id, x, y)



---

Реализация rebuild_all()

1. очистить canvas


2. взять все root-объекты:

document.get_root_entities()



3. для каждого создать view через add_view_for_entity(...)



На второй точке root-объекты — только leaf-объекты на FormRoot.


---

Реализация add_view_for_entity(...)

1. получить сущность из документа


2. создать inner_widget через WidgetFactory


3. создать LeafItemView


4. привязать сущность и widget


5. добавить на canvas


6. сохранить в item_views_by_id




---

Реализация refresh_view(...)

1. взять сущность


2. взять view


3. вызвать view.refresh_from_document(entity)


4. через factory обновить widget




---

Реализация select_entity(...)

1. сохранить selected_entity_id


2. пройтись по всем view


3. у выбранного set_selected(True)


4. у остальных set_selected(False)

Пример для кнопки:

{
  "meta": {
    "format_version": 1,
    "document_type": "pyside6_form"
  },
  "form": {
    "id": "form_root",
    "type": "FormRoot",
    "name": "form",
    "root_widget_type": "QWidget",
    "width": 1200,
    "height": 800,
    "window_title": ""
  },
  "objects": [
    {
      "id": "push_button_1",
      "type": "QPushButton",
      "parent_id": "form_root",
      "name": "push_button_1",
      "order": 0,
      "geometry": {
        "x": 100,
        "y": 80,
        "width": 120,
        "height": 32
      },
      "properties": {
        "text": "Button"
      }
    }
  ]
}

Добейся именно такого уровня корректности.
