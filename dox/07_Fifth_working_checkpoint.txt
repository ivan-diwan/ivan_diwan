Пятая рабочая контрольная точка

Собери строго это состояние:

работает QScrollArea как второй special-container

при добавлении QScrollArea автоматически создается ContainerContent

пользователь не видит ContainerContent как отдельный объект палитры

обычные объекты можно бросать внутрь QScrollArea

реальные дочерние объекты живут в ContainerContent, а не напрямую в QScrollArea

QScrollArea можно выбрать, двигать, менять размер, удалять

содержимое QScrollArea удаляется вместе с ним

JSON snapshot корректно отражает эту структуру


Не переходи дальше к QStackedWidget, пока этот блок не станет устойчивым.


---

1. Цель пятой контрольной точки

Закрой второй special-container паттерн:

внешний виджет-контейнер

скрытая внутренняя область содержимого

drop идет не в сам контейнер, а во внутреннюю служебную сущность


Пользователь должен мочь:

1. добавить QScrollArea


2. бросить внутрь кнопку


3. бросить внутрь label


4. двигать объекты внутри scroll area


5. двигать сам QScrollArea


6. менять размер QScrollArea


7. удалить QScrollArea вместе со всем содержимым




---

4. Реализация create_scroll_area(...)

Сделай строго так:

1. создать сущность QScrollArea


2. задать свойства:

widget_resizable = true



3. создать ContainerContent


4. назначить:

parent_id = scroll_area_id

order = 0

name = scroll_content_N



5. geometry ContainerContent задай как внутреннюю область:

x = 0

y = 0

width = width scroll area

height = height scroll area



6. записать обе сущности


7. пометить документ dirty


8. вернуть QScrollArea




---

5. Реализация get_scroll_content(...)

Сделай поиск среди прямых детей QScrollArea.

Требование:

у QScrollArea на этой точке должен быть ровно один ContainerContent


Если его нет:

возвращай None или

выбрасывай controlled error

11. Измени логику CanvasEditor.add_view_for_entity(...)

Сделай так:

Если тип = QScrollArea

1. получить сущность QScrollArea


2. получить его ContainerContent через документ


3. создать inner_widget для scroll area


4. создать content_widget для ContainerContent


5. создать ScrollAreaItemView


6. привязать все вместе


7. сохранить только view scroll area в item_views_by_id

Не создавай отдельный item_view для ContainerContent

Это важно для UX.

12. Доработай CanvasEditor.rebuild_all()

Рекурсивная сборка теперь должна учитывать special-case:

Если сущность — QScrollArea

build его как обычный видимый объект

потом children его ContainerContent должны строиться не как children QScrollArea, а как children внутреннего content_widget



---

Добавь helper

get_visual_parent_for_entity(entity)


Логика:

Если parent_id = form_root

визуальный родитель = корневой canvas

Если родитель — обычный контейнер

визуальный родитель = клиентская область контейнера

Если родитель — ContainerContent

визуальный родитель = content_widget соответствующего ScrollAreaItemView

Это ключевой сценарий пятой точки.

Если курсор попал в QScrollArea, настоящий parent_id для нового объекта должен быть:

3. перевести позицию в локальные координаты content area


4. вернуть:

14. Не показывай ContainerContent в палитре и в панели свойств как обычный объект

Зафиксируй строго:

пользователь не может создать ContainerContent

пользователь не видит его в палитре

пользователь не должен выбирать его как обычный объект на форме

пользователь не должен редактировать его как самостоятельную сущность


Весь доступ к нему идет только косвенно через QScrollArea.

16. Подключи обновление widget_resizable

При изменении через PropertyPanel:

1. PropertyPanel вызывает контроллер


2. контроллер вызывает document.update_property(...)


3. документ помечается dirty


4. canvas обновляет ScrollAreaItemView


5. JSON обновляется

17. Подключи выбор QScrollArea

Сценарий:

клик по пустой области внутри scroll area, но не по дочернему объекту
→ выбирается QScrollArea

клик по объекту внутри scroll area
→ выбирается дочерний объект


Для этого в ScrollAreaItemView реализуй hit testing так же, как для контейнеров.


---

18. Подключи move QScrollArea

Поведение:

QScrollArea двигается как единый объект

ContainerContent и его дети визуально едут вместе

geometry детей не пересчитывается

меняется только geometry самого QScrollArea


После завершения move:

документ обновляется

JSON обновляется

PropertyPanel показывает новые координаты



---

19. Подключи resize QScrollArea

Поведение:

меняется размер QScrollArea

внутренний content_widget живет внутри него

geometry детей не меняется

geometry ContainerContent можно синхронизировать с новой внутренней областью scroll area



---

Практическое правило для первой устойчивой версии

После resize QScrollArea:

обновляй geometry самого QScrollArea

при необходимости обновляй geometry ContainerContent

children не трогай



---

20. Обновляй ContainerContent.geometry осознанно

На этой точке сделай простое правило:

ContainerContent.geometry.width = текущая внутренняя ширина content area

ContainerContent.geometry.height = либо текущая высота content widget, либо не меньше высоты scroll area


Не усложняй авторасчет содержимого.
Пока достаточно согласованной модели.


---

21. Подключи удаление QScrollArea вместе с содержимым

Сценарий должен работать полностью.

Пользователь

Выбирает QScrollArea и удаляет.

Документ

Удаляет:

QScrollArea

ContainerContent

все дочерние объекты внутри ContainerContent


Canvas

Удаляет всю ветку

JSON

Очищается от этой структуры полностью


---

22. Доработай delete_subtree(...) с учетом ContainerContent

На уровне документа это уже обычная сущность.

Никаких специальных исключений в модели не делай.

Правило:

если удаляется QScrollArea

ContainerContent удаляется как его child

все объекты внутри ContainerContent удаляются рекурсивно
