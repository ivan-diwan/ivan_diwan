Подэтап I — QTreeWidget

Подключай QTreeWidget сразу после полного закрытия QTableWidget.
Архитектуру не меняй. Повтори тот же pipeline для древовидного leaf-виджета.


---

1. Цель подэтапа

Добейся, чтобы QTreeWidget проходил полный цикл:

есть в палитре

создается на форме

выбирается

двигается

меняет размер

редактируется через PropertyPanel

сохраняется в JSON

экспортируется в .py

импортируется обратно

проходит round-trip без потери geometry и свойств



---

2. Зафиксируй модель QTreeWidget

Считай QTreeWidget обычным leaf-объектом.

Тип

type_name = "QTreeWidget"


Роль

editor_kind = "leaf"


Палитра

palette_visible = true

palette_group = "Data"


Поведение

movable = true

resizable = true

deletable_directly = true


Qt-класс

qt_class_name = "QTreeWidget"



---

3. Зафиксируй минимальный набор свойств

Подключай только устойчивую базу.

Обязательные свойства

column_count: int

header_labels: list[str]


Значения по умолчанию

column_count = 1

header_labels = []


Что пока не подключай

Не добавляй на этом подэтапе:

tree items

раскрытие/сворачивание узлов

selection mode

sorting

uniform row heights

alternating row colors

indentation

root decoration

header hidden


Сначала закрой устойчивый базовый уровень структуры дерева.


---

Зафиксируй

type_name = "QTreeWidget"

palette_visible = true

palette_group = "Data"

required = true

default = 1

editor = "integer"


header_labels

data_type = "list[str]"

required = true

default = []

Разрешенные родители

Разреши:

FormRoot

QWidget

QFrame

QGroupBox

TabPage

StackPage

ToolPage

WizardPage

ContainerContent

SplitterPane


Разрешенные дети

allowed_child_types = None


Geometry mode

geometry_edit_mode = "full"

5. Проверь палитру

После добавления в registry проверь:

Tree Widget появился в группе Data

drag source передает type_name = "QTreeWidget"


Не переходи дальше, пока палитра не работает стабильно.


---

6. Подключи создание QTreeWidget в FormDocument

Специальной логики не нужно.
Используй обычный create_entity(...).

Проверь, что при создании:

берется default_size

создаются дефолтные properties

parent_id задается корректно

order считается корректно

документ помечается dirty



---

7. Добавь QTreeWidget в WidgetFactory

В factory/widget_factory.py добавь отдельную ветку.

В create_widget(entity)

Если entity.type == "QTreeWidget":

создавай QTreeWidget


В apply_properties(widget, entity)

Применяй:

1. setColumnCount(column_count)


2. setHeaderLabels(header_labels) — только если список не пуст




---

Порядок применения обязателен

Применяй именно так:

1. число колонок


2. заголовки




---

Почему это важно

Сначала должны существовать колонки.
Только потом корректно применяются заголовки.


---

8. Нормализуй длину header_labels относительно column_count

Сделай отдельный helper.

Например:

_normalize_tree_widget_properties(properties: dict) -> dict


Правило 1

Если column_count < 0:

ставь 0


Правило 2

Если header_labels отсутствует:

ставь []


Правило 3

Если header_labels не список:

приводи к списку строк


Правило 4

Все элементы header_labels приводи к str

Правило 5

Если длина header_labels больше column_count:

обрезай до column_count


Правило 6

Если column_count == 0:

header_labels = []



---

9. Не достраивай заголовки автоматически

На этой очереди не заполняй недостающие заголовки значениями вида:

Column 1

Column 2


Держи простое правило:

если список заголовков пустой, widget factory и exporter не задают labels

если список задан частично, применяется только он



---

10. Добавь refresh для QTreeWidget

Проверь, что refresh корректно переустанавливает:

column_count

header_labels


После изменения из PropertyPanel дерево на canvas должно обновляться без полного rebuild canvas.


---

11. Добавь QTreeWidget в PropertyPanel

Панель свойств должна показывать QTreeWidget как обычный leaf-объект.

Основное

type — read-only

name

parent — read-only


Геометрия

x

y

width

height


Свойства

column_count

header_labels


Типы редакторов

Используй:

column_count → QSpinBox

header_labels → string_list



---

12. Нормализуй flow изменений из PropertyPanel

Изменения должны идти только через контроллер.

Для column_count

update_entity_property(entity_id, "column_count", new_value)


Для header_labels

update_entity_property(entity_id, "header_labels", new_value)


После каждого изменения должен проходить единый pipeline:

1. изменение в документе


2. flush_json_snapshot()


3. canvas.refresh_view(entity_id)


4. property_panel.rebuild()




---

13. Учти зависимость заголовков от числа колонок

После изменения column_count обязательно прогоняй свойства через helper нормализации.

Это нужно, чтобы:

при уменьшении числа колонок обрезались лишние заголовки

документ всегда оставался валидным



---

14. Зафиксируй формат string_list для header_labels

Для header_labels используй тот же редактор:

одна строка = один заголовок


Не делай пока отдельную форму редактирования колонок.


---

15. Проверь работу CanvasEditor

QTreeWidget не требует специального item view.
Он должен работать через обычный LeafItemView.

Проверь, что он:

создается на canvas

выбирается

двигается

меняет размер

не ломает overlay

корректно обновляется после property changes



---

16. Проверь serializer

QTreeWidget не требует специальных JSON-веток.

Убедись, что в JSON попадают свойства в таком виде:

"properties": {
  "column_count": 3,
  "header_labels": ["Name", "Type", "Value"]
}

Проверь:

header_labels остается массивом строк

column_count остается int



---

17. Добавь экспорт QTreeWidget в PythonExporter

В exporter добавь отдельную ветку для QTreeWidget.

Генерируй

1. создание объекта


2. setObjectName(...)


3. setGeometry(...)


4. setColumnCount(...)


5. setHeaderLabels([...]) — если список не пуст



Пример

self.tree_widget_1 = QTreeWidget(self)
self.tree_widget_1.setObjectName("tree_widget_1")
self.tree_widget_1.setGeometry(100, 80, 200, 140)
self.tree_widget_1.setColumnCount(3)
self.tree_widget_1.setHeaderLabels(["Name", "Type", "Value"])


---

18. Не экспортируй tree items

На этой очереди не генерируй:

QTreeWidgetItem

addTopLevelItem

addChild


Если в модели нет элементов дерева, exporter не должен их придумывать.


---

19. Добавь импорт QTreeWidget в PythonImporter

На уровне AST-парсинга добавь поддержку:

QTreeWidget(parent)

setColumnCount(...)

setHeaderLabels(...)


Восстанавливай свойства

column_count

header_labels


После полного разбора прогоняй через helper нормализации.


---

20. Игнорируй tree items как unsupported case

Если importer встретил:

QTreeWidgetItem

addTopLevelItem(...)

addChild(...)


на этой очереди не пытайся восстанавливать элементы дерева.

Зафиксируй это как unsupported для текущей версии, если exporter сам этого не генерирует.

24. Зафиксируй критерий завершения QTreeWidget

Считай QTreeWidget полностью подключенным только если одновременно верно:

он есть в палитре

он создается drag&drop

он корректно отображается

его можно выбрать

его можно двигать и ресайзить

его свойства редактируются через PropertyPanel

свойства сохраняются в JSON

свойства экспортируются в Python

свойства импортируются обратно

round-trip не теряет структуру и значения

он стабильно работает внутри уже поддержанных контейнеров
