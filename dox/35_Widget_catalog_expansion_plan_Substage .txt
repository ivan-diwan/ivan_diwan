Вторая итерация — полностью раскрыть PropertyPanel по всем объектам

Работай без пересборки архитектуры.
Ничего не меняй в базовой модели документа, serializer, exporter/importer, canvas flow.


---

1. Цель

Доведи PropertyPanel до полного покрытия всех уже поддержанных объектов и всех внутренних сущностей системы.

Сделай единый принцип:

общий блок для всех объектов

типозависимый блок свойств

специальные блоки для special-container

internal-сущности редактируются только через родителя

все изменения идут только через DocumentController



---

2. Не менять

Не менять:

FormDocument как источник истины

JSON-формат

special-container структуру

create/move/resize/delete pipeline

exporter/importer архитектуру



---

3. Общая структура PropertyPanel

Для любого выбранного обычного объекта показывай блоки в одном порядке:

Блок A — Основное

type — read-only

name

parent — read-only


Блок B — Геометрия

x

y

width

height


Показывать только если geometry_edit_mode = full.

Блок C — Свойства типа

Показывать по schema объекта.

Блок D — Специальный блок

Только для:

QTabWidget

QScrollArea

QStackedWidget

QToolBox

QSplitter

QWizard



---

4. Internal-типы

Не показывай internal-типы как самостоятельные выбранные объекты формы:

TabPage

ContainerContent

StackPage

ToolPage

SplitterPane

WizardPage


Их редактирование делай только через родительские special-container блоки.


---

5. Общий mapping редакторов

Зафиксируй единый mapping:

text → QLineEdit

multiline → QPlainTextEdit

checkbox → QCheckBox

dropdown → QComboBox

integer → QSpinBox

float → QDoubleSpinBox

string_list → QPlainTextEdit, одна строка = один элемент

readonly → QLineEdit read-only



---

6. Поведение apply

Все изменения из PropertyPanel отправляй только через контроллер.

Используй только:

rename_entity(...)

update_entity_property(...)

update_entity_geometry(...)

специальные методы контейнеров:

add/remove/rename/set current page/tab/section

splitter orientation/sizes



После любого apply:

1. обновить документ


2. нормализовать свойства


3. flush_json_snapshot()


4. canvas.refresh_view(entity_id)
или canvas.rebuild_all() для структурных изменений


5. property_panel.rebuild()

12. Нормализация по семействам

Не размазывай правила по панели.
Все нормализации держи в helpers по типам.


---

Числовые

диапазон согласован

значение в диапазоне

step >= 1 или > 0 для float

digit_count >= 1

decimals >= 0


Текстовые

всегда str

placeholder всегда str

read_only → bool


Списковые

items/header_labels/... всегда list[str]

индексы согласованы с длиной списка


Табличные

размеры таблицы >= 0

длина заголовков не больше числа строк/столбцов


Date/Time

строки только в нормализованном формате

min/max согласованы

текущее значение внутри диапазона



---

13. Что сделать в коде

Сделай это в таком порядке.


---

Шаг 1

Приведи PropertyEditorFactory к полному покрытию редакторов:

text

multiline

checkbox

dropdown

integer

float

string_list

readonly



---

Шаг 2

Приведи WidgetRegistry.property_schema у всех типов к полному состоянию.


---

Шаг 3

Приведи PropertyPanel к сборке по schema из registry, а не по ручным веткам.

Оставь ручные ветки только для:

special-container блоков



---

Шаг 4

Добавь специальные блоки:

tabs

pages

sections

splitter sizes

wizard pages



---

Шаг 5

Проверь rebuild панели после:

property apply

selection change

structural change

load/import



---

14. Правило компактности кода

Не делай для каждого объекта отдельный hardcoded builder панели.

Делай так:

общий builder по schema

отдельные методы только для special-container секций


Оставь только такие специальные методы:

build_tab_widget_section(...)

build_scroll_area_section(...)

build_stacked_section(...)

build_toolbox_section(...)

build_splitter_section(...)

build_wizard_section(...)



---

15. Проверка завершения второй итерации

Закрывай эту итерацию только если:

Общая часть

любой поддержанный объект показывает полную панель

все поля отображаются правильным редактором

apply идет только через контроллер

JSON и canvas синхронизированы


Special-container часть

все internal-сущности редактируются только через родителя

все специальные блоки работают

rebuild после add/remove/rename/set current стабилен


Полнота покрытия

все объекты из текущего каталога имеют полный список свойств в панели

после этого к PropertyPanel по этим объектам больше не возвращаться



---

16. После этого

После закрытия этой итерации переходи не к панели свойств, а к углублению полезных объектов:

2. QTreeWidget — tree_items


3. при необходимости QListWidget — дополнительные полезные свойства
