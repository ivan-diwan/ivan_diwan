Шестая рабочая контрольная точка

Собери строго это состояние:

работает QStackedWidget как третий special-container

при добавлении QStackedWidget автоматически создаются две StackPage

StackPage не видны в палитре и не выбираются как обычные объекты формы

активная страница управляется только через PropertyPanel и сам QStackedWidget

обычные объекты можно бросать в активную страницу

реальные дочерние объекты живут в StackPage, а не напрямую в QStackedWidget

можно добавлять страницы

можно удалять страницы

можно переименовывать страницы

можно переключать активную страницу

корректно обновляется JSON snapshot

корректно удаляется QStackedWidget вместе со всеми страницами и содержимым


Не переходи к QToolBox, пока этот блок не станет устойчивым.


---

1. Цель шестой контрольной точки

Закрой второй page-based контейнер, но уже без визуальных вкладок.

Пользователь должен мочь:

1. добавить QStackedWidget


2. увидеть, что у него есть минимум две страницы


3. управлять страницами через панель свойств


4. переключать активную страницу


5. добавлять объекты в первую страницу


6. переключаться на вторую страницу


7. добавлять туда другие объекты


8. удалять страницы


9. удалять весь QStackedWidget вместе со всем содержимым




---

4. Реализация create_stacked_widget(...)

Сделай строго так:

1. создать сущность QStackedWidget


2. задать свойства:

current_index = 0



3. создать первую StackPage


4. создать вторую StackPage


5. назначить им:

parent_id = stacked_widget_id

order = 0 и order = 1

properties["title"] = "Page 1" и "Page 2"



6. пометить документ dirty


7. вернуть QStackedWidget




---

5. Реализация add_stack_page(...)

Сделай:

1. проверить существование QStackedWidget


2. получить текущие StackPage


3. вычислить следующий order


4. создать новую StackPage


5. задать title:

если передан — использовать его

если нет — "Page N"



6. сделать новую страницу активной


7. пометить документ dirty


8. вернуть созданную StackPage




---

6. Реализация remove_stack_page(...)

Сделай аккуратно.

Алгоритм

1. проверить существование QStackedWidget


2. проверить, что stack_page_id действительно child этого QStackedWidget


3. удалить все дочерние объекты StackPage


4. удалить саму StackPage


5. перестроить order оставшихся страниц


6. скорректировать current_index




---

Ограничение

Не разрешай удалить последнюю страницу.

Зафиксируй правило:

у QStackedWidget должна оставаться минимум одна StackPage



---

13. Не создавай отдельный обычный view для StackPage

14. Реализуй rebuild_pages(...) у StackedWidgetItemView

Делай так:

1. очистить текущие страницы в QStackedWidget


2. получить StackPage из документа


3. отсортировать по order


4. для каждой страницы:

создать внутренний QWidget

добавить его в QStackedWidget

сохранить соответствие:

stack_page_id -> page_widget




5. выставить активную страницу по current_index

16. Подключи переключение страниц

Если пользователь переключает страницу программно через панель свойств

2. контроллер вызывает set_current_stack_page(...)

Это проще и чище.
