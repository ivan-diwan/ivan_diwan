Подэтап G — QListWidget

Подключай QListWidget сразу после полного закрытия QPlainTextEdit.
Архитектуру не меняй. Повтори тот же pipeline для спискового leaf-виджета.


---

1. Цель подэтапа

Добейся, чтобы QListWidget проходил полный цикл:

есть в палитре

создается на форме

выбирается

двигается

меняет размер

редактируется через PropertyPanel

сохраняется в JSON

экспортируется в .py

импортируется обратно

проходит round-trip без потери geometry и свойств



---

2. Зафиксируй модель QListWidget

Считай QListWidget обычным leaf-объектом.

palette_group = "Data"


Поведение

resizable = true

deletable_directly = true


Qt-класс

qt_class_name = "QListWidget"

Значения по умолчанию

Проверь, что при создании:

7. Добавь QListWidget в WidgetFactory

В factory/widget_factory.py добавь отдельную ветку.

В create_widget(entity)

Если entity.type == "QListWidget":

создавай QListWidget


В apply_properties(widget, entity)

Применяй:

1. clear()


2. addItems(items)


3. setCurrentRow(current_row) — только если индекс допустим


4. если current_row = -1, явно сбрасывай текущий выбор




---

Правильный порядок применения

1. очистка


2. добавление элементов


3. установка текущей строки




---

Почему это важно

Если сначала установить current_row, а потом перезаполнить список, выбор уйдет.


---

8. Сделай явный reset current row

Если current_row:

меньше 0

или больше последнего индекса списка


не вызывай setCurrentRow(...).

Для надежности после clear() и addItems(...) делай:

либо ничего

либо setCurrentRow(-1), если в Qt это работает устойчиво в твоей реализации


Если setCurrentRow(-1) ведет себя нестабильно, просто не вызывай его.

11. Нормализуй flow изменений из PropertyPanel

Изменения должны идти только через контроллер.

Для items

update_entity_property(entity_id, "items", new_items)


Для current_row

update_entity_property(entity_id, "current_row", new_value)


После каждого изменения должен проходить единый pipeline:

1. изменение в документе


2. flush_json_snapshot()


3. canvas.refresh_view(entity_id)


4. property_panel.rebuild()




---

12. Добавь нормализацию свойств QListWidget

Сделай отдельный helper.

Например:

_normalize_list_widget_properties(properties: dict) -> dict


Правило 1

Если items отсутствует:

ставь []


Правило 2

Если items не список:

приводи к списку строк через безопасную нормализацию


Правило 3

Каждый элемент items приводи к str

Правило 4

Если current_row < -1:

ставь -1


Правило 5

Если список пуст:

current_row = -1


Правило 6

Если current_row >= len(items):

ставь -1 или

последний допустимый индекс


Для устойчивой первой версии делай:

current_row = -1



---

13. Зафиксируй формат string_list редактора

Для items используй тот же редактор, что уже есть для других string list свойств.

Принцип:

одна строка = один элемент списка



---

При чтении из редактора

1. разбей текст по строкам


2. убери только завершающие пустые строки, если это нужно


3. оставшиеся строки сохраняй как items




---

Не делай пока

отдельные кнопки add/remove item

drag сортировку строк внутри редактора

inline-таблицу для items


Сначала держи один устойчивый multiline pipeline.

15. Проверь serializer

QListWidget не требует специальных JSON-веток.

Убедись, что в JSON попадают свойства в таком виде:

"properties": {
  "items": ["Первый", "Второй", "Третий"],
  "current_row": 1
}

Проверь:

items остается массивом строк

current_row остается int

16. Добавь экспорт QListWidget в PythonExporter

В exporter добавь отдельную ветку для QListWidget.

Генерируй

1. создание объекта


2. setObjectName(...)


3. setGeometry(...)


4. addItems([...]) — если список не пуст


5. setCurrentRow(...) — если индекс допустим



Пример

self.list_widget_1 = QListWidget(self)
self.list_widget_1.setObjectName("list_widget_1")
self.list_widget_1.setGeometry(100, 80, 170, 110)
self.list_widget_1.addItems(["Первый", "Второй", "Третий"])
self.list_widget_1.setCurrentRow(1)

Не генерируй setCurrentRow(...), если:

current_row = -1

список пуст

индекс вне диапазона
