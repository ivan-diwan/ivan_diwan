Третья рабочая контрольная точка

Собери строго это состояние:

на форме работают обычные контейнеры

можно добавить QWidget, QFrame, QGroupBox

можно бросать leaf-объекты внутрь контейнеров

координаты дочерних объектов считаются относительно контейнера

можно выбрать контейнер кликом по его пустой области

можно двигать контейнер

можно менять размер контейнера

можно удалить контейнер вместе со всем его содержимым

JSON корректно отражает вложенную структуру


До завершения этой точки не переходи к:

QTabWidget

QScrollArea

QStackedWidget

QToolBox

QSplitter

QWizard



---

1. Цель третьей контрольной точки

Закрой полностью первый уровень вложенности формы.

Пользователь должен уже мочь:

1. создать контейнер


2. бросить в него кнопку или label


3. выбрать контейнер


4. выбрать объект внутри контейнера


5. двигать контейнер


6. менять размер контейнера


7. удалить контейнер вместе с дочерними объектами



После этого геометрическая модель станет реально рабочей.


---

2. Типы, которые подключай на этой точке

Подключай только:

Обычные контейнеры

QWidget

QLabel

QPushButton

Сначала стабилизируй вложенность именно на этом наборе.

И все container-поведение как у QWidget.


---

У QGroupBox

Зафиксируй:

свойства:

title

checkable

checked



И все container-поведение как у QWidget.

4. Расширь FormDocument для нормальной работы с поддеревом

Доведи методы:

get_descendants(parent_id)

delete_subtree(entity_id)



---

Реализация get_descendants(parent_id)

Сделай рекурсивно или итеративно.

Требование:

вернуть все вложенные сущности любого уровня глубины



---

Реализация delete_subtree(entity_id)

Логика:

1. получить всех потомков


2. отсортировать их так, чтобы сначала удалялись дети глубже


3. удалить всех потомков


4. удалить сам объект


5. пометить документ dirty

5. Добавь в CanvasEditor поддержку drop в контейнеры

На этой точке CanvasEditor должен уметь определять:

drop на FormRoot

drop внутрь QWidget

drop внутрь QFrame

drop внутрь QGroupBox



---

Сделай в CanvasEditor

resolve_drop_parent(pos) -> parent_id

find_topmost_container_at(pos) -> entity_id | "form_root"



---

Правило выбора родителя

Если курсор внутри контейнера:

родителем становится контейнер


Если курсор не внутри ни одного контейнера:

родитель = form_root



---

Важно

Листовые объекты не могут быть drop-target.

8. Сделай get_content_origin() у контейнеров

Это обязательный метод для правильных локальных координат.


---

Для QWidget

content_origin = (0, 0)


---

Для QFrame

На первой точке тоже можно: content_origin = (0, 0)


---

Для QGroupBox

Нужно учитывать верхнюю зону заголовка.

Сделай упрощенно:

фиксированный отступ сверху, например 24

content_origin = (0, 24)


Потом можно будет уточнить по реальному клиентскому rect.

9. Подключи ContainerItemView в CanvasEditor

В CanvasEditor.add_view_for_entity(entity_id) сделай dispatch:

Если editor_kind == "leaf"

создавай LeafItemView

Если editor_kind == "container"

создавай ContainerItemView

На этой точке этого достаточно.

10. Сделай правильное визуальное размещение дочерних объектов

На этой точке объект внутри контейнера должен размещаться:

не на корневом canvas напрямую

а внутри визуальной области контейнера



---

Правило

Если у сущности:

parent_id = form_root

рисуй ее как прямой child canvas



Если у сущности:

parent_id = container_id

рисуй ее внутри ContainerItemView этого контейнера




---

Для этого добавь в CanvasEditor

get_view(entity_id)

get_parent_view(entity_id)

get_visual_parent_for_entity(entity)

11. Перестрой rebuild_all()

Сделай полную перестройку на основе parent-child.


---

Логика

1. очистить canvas


2. взять все root-объекты


3. рекурсивно строить дерево view




---

Добавь метод

build_entity_subtree(entity_id, visual_parent)



---

Алгоритм build_entity_subtree

1. создать view для сущности


2. вставить ее в visual_parent


3. взять детей сущности из документа


4. отсортировать детей по order


5. рекурсивно построить их subtree




---

19. Подключи move контейнера

Контейнер должен двигаться как единый объект.


---

Поведение

Во время drag:

двигается только контейнер визуально

дети визуально двигаются вместе с ним, потому что они внутри него


После mouse release:

меняется только geometry контейнера

geometry детей остается прежней, локальной



---

Это обязательно

Не пересчитывай дочерние координаты при обычном перемещении контейнера.


---

20. Подключи resize контейнера

Контейнер должен менять размер как единый объект.


---

Поведение

Во время resize:

контейнер визуально меняет размер

дети остаются внутри него


После resize:

меняется только width/height контейнера

children geometry не меняется



---

Не делай пока

автоматическое растяжение детей

layout-реакцию

anchors



---

21. Подключи удаление контейнера вместе с содержимым

Сценарий должен работать полностью.


---

Пользователь

Выбирает контейнер и нажимает удалить.

Контроллер

Вызывает:

delete_entity(container_id)


Документ

Если объект контейнер:

удаляет все поддерево


Canvas

Удаляет:

view контейнера

view всех дочерних объектов


PropertyPanel

Переходит в режим формы

JSON

Обновляется


---

22. Сделай корректную полную перестройку canvas после удаления контейнера

На этой точке проще и надежнее после удаления контейнера делать:

rebuild_all()


чем пытаться точечно удалять все вручную.

Для обычного удаления leaf-объекта можно точечно.
Для контейнера с поддеревом лучше сразу полный rebuild.

23. Доработай JSON для вложенной структуры

Проверь, что вложенный объект внутри контейнера записывается так:

{
  "id": "push_button_1",
  "type": "QPushButton",
  "parent_id": "group_box_1",
  "name": "push_button_1",
  "order": 0,
  "geometry": {
    "x": 20,
    "y": 30,
    "width": 120,
    "height": 32
  },
  "properties": {
    "text": "Button"
  }
}

Ключевой момент:

parent_id = group_box_1

x/y локальные относительно контейнера

26. На этой точке не делай вложенные контейнеры глубже одного уровня специально

Архитектура должна выдерживать рекурсию, но вручную пока тестируй стабильно такие сценарии:

контейнер на форме

После стабилизации проверь:

контейнер в контейнере

leaf внутри внутреннего контейнера


Но не переходи дальше, пока базовый уровень не станет устойчивым.
