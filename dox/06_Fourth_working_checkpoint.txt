Четвертая рабочая контрольная точка

Собери строго это состояние:

работает QTabWidget как первый special-container

при добавлении QTabWidget автоматически создаются две TabPage

на canvas вкладки отображаются визуально

можно переключать активную вкладку

можно бросать обычные объекты в активную вкладку

объекты внутри вкладок живут в TabPage, а не напрямую в QTabWidget

можно добавлять вкладки

можно удалять вкладки

можно переименовывать вкладки

корректно обновляется JSON snapshot

корректно удаляется QTabWidget вместе со всеми страницами и содержимым


Не переходи дальше к QScrollArea, пока этот блок не станет устойчивым.


---

1. Цель четвертой контрольной точки

Закрой первый полноценный page-based контейнер.

Пользователь должен уже мочь:

1. добавить QTabWidget


2. увидеть две вкладки


3. переименовать вкладки


4. переключать активную вкладку


5. добавить кнопку в первую вкладку


6. добавить label во вторую вкладку


7. удалить вкладку


8. удалить весь QTabWidget вместе с содержимым



После этого модель special-container будет реально подтверждена.


---

5. Реализация create_tab_widget(...)

Сделай строго так:

1. создать сущность QTabWidget


2. задать:

current_index = 0

tabs_closable = false



3. создать первую TabPage


4. создать вторую TabPage


5. назначить им:

parent_id = tab_widget_id

order = 0 и order = 1

title = "Tab 1" и title = "Tab 2"
или "Tab" + индекс



6. пометить документ dirty


7. вернуть сущность QTabWidget




---

6. Реализация add_tab_page(...)

Сделай строго так:

1. проверить существование QTabWidget


2. получить текущие TabPage


3. вычислить следующий order


4. создать новую TabPage


5. задать title

если не передан, сделать "Tab N"



6. добавить сущность в документ


7. при необходимости:

сделать новую вкладку активной
или

оставить активной текущую




Для первого рабочего варианта делай:

новая вкладка становится активной



---

7. Реализация remove_tab_page(...)

Сделай аккуратно.


---

Алгоритм

1. проверить существование QTabWidget


2. проверить, что tab_page_id действительно child этого QTabWidget


3. удалить все дочерние объекты TabPage


4. удалить саму TabPage


5. перестроить order оставшихся страниц


6. скорректировать current_index




---

Правило для current_index

Если удалена активная вкладка:

активной должна стать предыдущая

если предыдущей нет — первая оставшаяся

если вкладок не осталось, надо не допускать такое состояние



---

Ограничение

Не разрешай удалить последнюю вкладку, если в системе зафиксировано, что у QTabWidget всегда должна быть хотя бы одна страница.

Для практичного первого варианта зафиксируй:

у QTabWidget должно оставаться минимум одна TabPage



---

12. Реализуй WidgetFactory для QTabWidget

В factory/widget_factory.py добавь поддержку:

QTabWidget

TabPage



---

Для QTabWidget

Создавай реальный QTabWidget.

Применяй:

geometry

current_index

tabs_closable


Но сами страницы не собирай здесь полностью.
Страницы собирай в TabWidgetItemView, потому что это уже визуальная структура редактора.


---

Для TabPage

Как отдельный внешний элемент factory можешь не создавать пользовательский виджет напрямую.
Внутри QTabWidget используй QWidget как визуальную страницу.

Главное:

TabPage существует как сущность документа

визуально она отображается внутри QTabWidget

15. Построй визуальные страницы вкладок

В TabWidgetItemView.rebuild_tabs(...) сделай:

1. удалить текущие вкладки из inner_widget


2. получить все TabPage из документа


3. отсортировать по order


4. для каждой TabPage

5. установить активную вкладку по current_index

16. Отображай дочерние объекты TabPage

Каждый объект, у которого:

parent_id = tab_page_id


должен визуально строиться внутри страницы этой вкладки, а не внутри самого QTabWidget.


---

Для этого в CanvasEditor

добавь логику:

get_visual_parent_for_entity(entity)


Если родитель = TabPage, то визуальный родитель = внутренняя QWidget-страница соответствующего QTabWidget.

17. Не показывай TabPage как объект палитры и как обычный объект canvas

TabPage:

не должен появляться в палитре

не должен показываться как отдельный прямоугольник поверх формы

не должен выделяться как обычный leaf/container объект по клику на форме


Редактирование TabPage идет:

через QTabWidget

через блок управления вкладками в PropertyPanel

18. Реализуй переключение активной вкладки

Сделай двустороннюю синхронизацию.


---

Если пользователь переключил вкладку мышью в QTabWidget

1. TabWidgetItemView ловит смену индекса


2. сообщает CanvasEditor


3. canvas передает контроллеру


4. контроллер вызывает set_current_tab(...)


5. документ обновляется


6. JSON обновляется




---

Если пользователь сменил current_index через PropertyPanel

1. PropertyPanel вызывает контроллер


2. контроллер меняет документ


3. canvas обновляет QTabWidget
