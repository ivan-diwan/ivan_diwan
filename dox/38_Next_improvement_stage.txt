Следующий этап улучшения системы после закрытия текущей линии каталога

Этот этап начинается после фиксации рабочего ядра конструктора и после
закрытия текущей документированной линии расширения каталога виджетов.

На этом этапе не нужно возвращаться к пересборке основы.
Нужно усиливать уже собранную систему по отдельным направлениям, не смешивая их.


---

1. Главное правило этапа

Работать только малыми независимыми проходами.

Не смешивать в одном проходе:

UX редактора
усиление export/import
тестовую инфраструктуру
новые большие архитектурные блоки

Каждый проход должен иметь:

четкую область
четкие файлы
четкие критерии завершения


---

2. Приоритеты этапа

Работать в таком порядке:

1. feedback layer для пользователя
2. диагностика importer/exporter
3. test-support layer
4. UX-полировка редактора
5. локальное расслоение крупных файлов


---

3. Подэтап 1 — Feedback Layer

Это первый обязательный практический шаг.

Цель:

перестать терять важные ошибки в консоли
дать пользователю короткие статусные сообщения
сделать управляемое отображение ошибок в UI

Не менять архитектуру документа, controller pipeline и serializer/exporter/importer contract.

Менять только presentation layer и связанные boundary-методы.


---

4. Что должно появиться в Feedback Layer

Минимальный обязательный результат:

1. короткие статусные сообщения в главном окне

Показывать:

форма создана
форма загружена
JSON сохранен
Python экспортирован
Python импортирован


2. controlled error presentation

Показывать пользователю ошибки:

невозможная загрузка JSON
невозможный import Python
ошибка export
ошибка save/load
ошибка validation
drop rejected


3. отдельная область или механизм накопления ошибок

Минимально допустимо:

error log panel
или read-only log view в главном окне
или отдельный dockable/error section

Главное:

ошибка не должна теряться только в print()
ошибка не должна показываться только traceback в терминале


---

5. Что менять в этом подэтапе

Допустимые точки изменений:

ui/main_editor/main_editor_window.py
ui/form_window/form_window.py
canvas/canvas_editor.py
controller/document_controller.py

Допустимо добавить:

новый UI-виджет для логов ошибок
новые controller signals для status/error feedback


---

6. Что запрещено делать в этом подэтапе

Не начинать:

undo/redo
copy/paste
multi-select
новый каталог виджетов
новую data architecture
глубокий рефакторинг importer/exporter

Не менять:

FormDocument как источник истины
общий JSON contract
общий round-trip pipeline


---

7. Критерии завершения подэтапа 1

Подэтап считается закрытым только если:

1. пользовательские успешные операции дают короткий status feedback
2. ошибки load/save/export/import показываются в UI, а не теряются в консоли
3. reject недопустимого drop тоже виден пользователю
4. существующий workflow не ломается
5. есть smoke-проверка нового feedback слоя


---

8. Подэтап 2 — Diagnostics Layer

После feedback layer усиливать диагностику importer/exporter.

Цель:

сделать ошибки не только видимыми, но и объяснимыми

Что должно появиться:

структурированная диагностика importer
подробный unsupported report
привязка к строке или AST-pattern там, где это возможно

Этот подэтап должен идти отдельно от feedback layer.


---

9. Подэтап 3 — Test Support Layer

После diagnostics layer усилить тестовую основу.

Что добавить:

единый helper compare_documents(doc_a, doc_b)
единый helper document_signature(...)
уменьшение дублирования signature logic в тестах
дополнительные unit-level tests для normalization/validator/helper-слоев


---

10. Подэтап 4 — UX Polish Layer

После feedback/diagnostics/test-support переходить к улучшению редакторского UX.

Приоритет внутри этого слоя:

1. palette search и collapse/expand групп
2. status-friendly read-only и list editors
3. selection overlay / resize handles / hover feedback
4. drop-highlight и явный UX-запрет недопустимого drop


---

11. Подэтап 5 — Local Decomposition

Только после того как поведение стабилизировано, локально расслоить крупные файлы:

property_panel.py
importer.py
exporter.py
builtins.py

Это не должен быть абстрактный рефакторинг.
Его нужно делать только после закрепления поведения предыдущих слоев.


---

12. Следующий практический шаг

Начинать прямо с Подэтапа 1 — Feedback Layer.

Минимальный первый проход:

1. добавить status feedback в MainEditorWindow
2. добавить controlled error log view
3. убрать print-only поведение для drop rejected
4. связать controller/UI так, чтобы load/save/export/import ошибки доходили до пользователя
5. добавить smoke-тест на feedback layer
