Десятая рабочая контрольная точка

Доведи PropertyPanel до полного рабочего состояния для всей уже собранной системы.

Собери строго это состояние:

панель свойств работает единообразно для формы, обычных объектов, контейнеров и special-container типов

для каждого свойства используется корректный тип редактора

read-only поля отображаются отдельно и не редактируются

geometry у internal-типов скрыта или read-only по правилам registry

специальные блоки работают для:

QTabWidget

QToolBox

QStackedWidget

QWizard

QSplitter


любое изменение из панели проходит только через DocumentController

после любого завершенного изменения корректно обновляются:

FormDocument

CanvasEditor

JSON snapshot


панель не содержит захардкоженной хаотичной логики по типам, а опирается на WidgetRegistry


После этого переходи к PythonExporter.


---

1. Цель десятой контрольной точки

Сделай PropertyPanel полноценным рабочим инструментом редактора.

Пользователь должен мочь:

1. выбрать любой уже поддержанный объект


2. увидеть его свойства в понятной структуре


3. изменить значения через правильные редакторы


4. сразу получить обновление объекта на форме


5. получить корректный JSON snapshot



После этого панель свойств можно считать закрытой как отдельный архитектурный модуль.


---

18. Подключи единое применение изменений через контроллер

Запрети прямое изменение документа из PropertyPanel.

Сделай только один путь:

PropertyPanel → DocumentController → FormDocument



---

Для этого в PropertyPanel

не меняй сущности напрямую.
Вызывай только методы контроллера:

rename_entity(...)

update_entity_property(...)

update_entity_geometry(...)

специальные методы контейнеров



---

19. Нормализуй flow любого изменения

После любого завершенного изменения из панели выполняй один и тот же цикл:

1. пользователь меняет значение


2. PropertyPanel вызывает метод контроллера


3. контроллер меняет FormDocument


4. контроллер вызывает flush_json_snapshot()


5. контроллер вызывает обновление canvas


6. контроллер вызывает обновление PropertyPanel



Не делай разных обходных путей для разных типов.


---

20. Раздели полное обновление и частичное обновление

Сделай два режима.


---

Для обычных свойств leaf/container объектов

Используй:

canvas.refresh_view(entity_id)



---

Для special-container структурных действий

Используй:

canvas.rebuild_all()
или

canvas.refresh_view(container_id) если уже устойчиво реализовано


Для первой устойчивой версии оставь:

rebuild_all() на структурные действия

22. Приведи PropertyPanel к схеме “rebuild from current selection”

Сделай один устойчивый путь:

получить текущее выделение из контроллера

если ничего не выбрано → показать FormRoot

если выбрана сущность → построить панель по типу этой сущности


Не обновляй куски панели вручную хаотично.

После любого существенного изменения вызывай:

PropertyPanel.rebuild()

30. Проверь корректную работу read-only и hidden логики

Закрой это отдельно.


---

У internal-типов

Не показывай geometry как обычный редактируемый блок.

---

У формы

Не показывай parent, потому что у формы его нет.

32. Что должно быть следующим шагом

После устойчивой PropertyPanel переходи к:

Одиннадцатая рабочая контрольная точка — PythonExporter

Собирай в таком порядке:

1. экспорт FormRoot


2. экспорт базовых leaf-объектов


3. экспорт обычных контейнеров


4. экспорт QTabWidget


5. экспорт QScrollArea


6. экспорт QStackedWidget


7. экспорт QToolBox


8. экспорт QSplitter


9. экспорт QWizard


10. формирование стабильного .py файла из FormDocument



Exporter строй только из документа.
Никогда не строй exporter из canvas или из live QWidget-дерева.
